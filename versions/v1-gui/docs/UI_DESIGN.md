# RazerMate 界面设计说明

## 目标与约束

- 全中文界面，只针对 Basilisk V3 有线版，不兼容其他鼠标。
- 界面显示的每个数值都来自设备实测，不写死。
- 极低内存：不用位图当 UI 皮肤，不播放常驻动画，宁可少一层装饰。
  后台 agent 尤其严格，不链入 Slint GUI。
- 只有两处静态图片是必须的：应用图标（`razer-logo.svg`）和真机渲染图
  （`basilisk.png`，由设备照片抠底而来）——它们承载「这是哪台设备」的信息，
  画不出来。其余图标、进度条、光晕全部是 Slint 原生几何与渐变绘制。

## 参考依据

**Apple Human Interface Guidelines**

- 设计原则：Purpose / Agency / Familiarity / Simplicity / Craft / Delight——
  「清晰的层级」「一致的行为」「明确的反馈」「每个元素都要有存在理由」。
- Layout：按重要性排序、对齐与缩进表达层级、用留白和容器分组、渐进披露。
- Typography：macOS 正文 13pt 为默认、10pt 为下限；避免细字重；用字号、
  字重、颜色三者共同建立层级；尽量只用一种字体（微软雅黑 UI）。
- Accessibility：≤17pt 文字至少 **4.5:1** 对比度（WCAG AA）；控件最小
  28×28；禁用态也要能看清。

**Basilisk V3 产品图与配置界面参考图**

- 黑色磨砂机身 + 雷蛇绿 + 底盘 RGB 光晕 → 中性深色灰阶、绿色作为唯一强调色、
  1 条 2px 的 RGB 细条作为品牌呼应（纯色块，零贴图）。
- 参考界面的卡片化分区、鼠标视觉锚点、性能与槽位卡片 → 保持侧栏 + 卡片布局；
  概览页主卡放真机渲染图作视觉主体，其余页面不贴图。

## 配色与对比度

底色压到接近纯黑（带一点蓝），卡片靠「三级台阶」浮起来：
底 `#080A0E` → 卡 `#151A21` → 卡内浮层 `#1D232C`。对比度按卡片底 `#151A21` 计。

| 用途 | 色值 | 对卡片底对比度 |
|---|---|---|
| 主文字 | `#F5F7FB` | 16.29:1 |
| 次级文字 | `#A3ADBB` | 7.70:1 |
| 辅助文字（10.5px 小字也用它） | `#838F9E` | 5.32:1 |
| 强调色（雷蛇绿） | `#46D92D` | 9.34:1 |
| 强调色高光 / 按钮渐变终点 | `#7BF25C` | — |
| 指标色：紫 / 蓝 / 橙 | `#A78BFA` / `#4C9DFF` / `#FFAB4A` | 6.42 / 6.30 / 9.30:1 |
| 卡片底 / 浮层 / 输入底 | `#151A21` / `#1D232C` / `#0E1218` | — |
| 窗口底 / 侧栏 | `#080A0E` / `#0A0C11` | — |
| 描边（8% 白） | `#FFFFFF14` | — |

绿色只出现在「当前/成功/主操作」：选中导航、当前槽、生效档位、主按钮。
紫/蓝/橙只做四张指标卡的识别色与卡片图标，不进入文字层级。

背景是两层：一层纵向渐变 + 四团低透明度径向光晕（左上一团绿、右上蓝、
右下紫、左下一团绿，alpha 8%~15%），只是让大片暗部不死板，卡片对比度不受影响。

## 版式规范

- 字号阶梯：10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 16 / 18 / 19 / 20 / 25px。
- 控件高度：导航项 38px、按钮 34px、Chip 30px、输入框 34px、行 28px。
- 圆角：卡片 14px、指标卡 14px、按钮与输入 9px、Chip 15px、卡片内浮层 10px。
- 间距：卡片内边距 14–18px、卡片间距 12–14px、内容区边距 22px。
- 卡片自带标题（图标底 + 标题 + 右侧说明），不再在卡片外面挂一条分组标题。
- 侧栏：logo + 版本名 + 导航 + 底部「重新读取设备」；选中项是实心绿胶囊，
  深色字配 4px 绿色投影。

## 界面改动

1. **导航**：每项配一枚纯几何图标（16×16，零贴图），三组分组标题，选中态保留
   绿色指示条并加粗文字。
2. **顶栏**：标题 19px + 副标题 12px + 带圆点的状态徽章；下方 2px RGB 五色细条。
3. **设备卡**：`B3` 标识下加 RGB 小条；设备标识改为简短的
   `USB HID · 1532:0099 · 控制口 MI_03`；固件与模式改为徽章。
4. **统计卡**：数值放大到 21px，顶部 3px 色条；仅「当前生效槽」使用绿色。
5. **控件统一**：按钮、Chip、色块、滑条拇指、行内小按钮统一圆角与最小尺寸；
   滑条拇指改为带绿环的圆点；修复禁用主按钮的近黑字问题。
6. **分组标题**：卡片内小节标题左侧加绿色细条，与侧栏选中态呼应。
7. **空状态**：宏列表为空时显示带图标的引导卡片，而不是一行灰色小字。
8. **状态栏**：去掉 100+ 字符的 HID 路径，只保留产品名；完整路径仍可用
   `razerctl info` 查看。
9. **按键参数不再手填**（P9）：按动作类型改成点选 / 录入——
   - 鼠标键：9 个鼠标动作 Chip 两行列全（左 / 右 / 中 / 后退 / 前进 / 滚轮上下 / 左右倾）；
   - 组合键：复制 / 粘贴 / 剪切 / 全选 / 保存 / 撤销 / 重做 / Alt+Tab 共 8 个预设 Chip，
     另有「录入组合键」——按下后捕获真实键盘事件（含 Ctrl / Shift / Alt / Win 修饰键），
     自动生成 `ctrl+c` 这类参数；
   - DPI 动作 / 媒体键：3 个与 7 个 Chip 分别列全；
   - 宏：直接列出 Flash 中已有宏点选，播放次数另用 1 / 2 / 3 次 Chip；
   - 手填输入框折叠为「手动输入（高级）」，仅覆盖预设之外的罕见值。
   这样符合 Apple HIG 的「recognition rather than recall」：看得见、点得到，不用记协议串。
10. **窗口可缩放**：Slint 中给 `Window` 写死 `width/height` 会被当作固定尺寸，
    winit 据此禁用最大化按钮。改用 `preferred-width/height` 给初始 `980×680`、
    `min-width/height` 给下限，最大化与拖拽缩放均可用，内容区随窗口自适应拉宽。
11. **统计卡色条内缩**：顶部 3px 色条左右各内缩 12px（大于 10px 圆角）并改成胶囊形，
    不再压在卡片圆角上，与整体圆角语言一致。
12. **运行模式提到顶栏 + 功能随模式走**：顶栏右侧加「运行模式」分段开关
    （离线 / 在线，一眼可见、随手可切），不再藏在自动切换页底部。功能可见性跟模式走：
    - **离线模式**：侧栏无「在线模式 / 自动切换」入口，只显示板载 5 槽能力；
    - **在线模式**：侧栏出现「在线模式 / 自动切换」，解锁无限虚拟槽、按程序自动切宏、
      三区灯效独立配置。
    概览页新增「运行模式」卡片，用两张对比卡讲清两种模式的能力差异并提供切换按钮；
    切回离线时若停在在线专属页会自动跳回概览。
13. **三区灯效独立配置**（在线模式）：虚拟槽编辑区从只有灯带一区扩展为灯带 / Logo / 滚轮
    三区，每区独立选择静态（含颜色）/ 光谱 / 波浪与亮度滑条。
14. **术语分层**，消除混淆：顶栏「运行模式 = 离线 / 在线」是程序行为；
    设备卡与状态栏的「设备层 · 普通 (0) / 驱动 (3)」是 HID 协议层状态
    （驱动层只在写 DPI 时短暂切入）。两者不再是同一个词。
15. **徽章圆点垂直居中**：Badge 里 6px 圆点原先直接放在 HorizontalLayout 中，
    Slint 默认按顶部对齐，导致圆点跑出徽章框左上角（用户截图反馈「字体对不齐」）。
    改为用 `VerticalLayout { alignment: center }` 包裹圆点，并把徽章宽度计入圆点占位，
    现在所有徽章（固件 / 设备层 / 在线模式 / 已连接）圆点都在框内与文字垂直居中。
    虚拟槽三区灯效的颜色块同样加了居中包裹，避免同类贴顶问题。

16. **顶栏与状态栏精简**（用户反馈「运行模式四个字删掉、已连接到处是」）：
    顶栏右侧只留「离线 / 在线」分段开关（删掉上方「运行模式」小标签与「已连接」徽章），
    左侧只留页面标题（删掉每页副标题）；状态栏删掉左侧连接状态与右侧固件 / 设备层文字，
    连接状态（圆点 + 文字）移到右下角。
17. **全局删减说明性小字**（用户反馈「上位机不是说明书」）：删除概览页运行模式对比卡、
    「当前处于 X 工作层」说明卡、FLASH 卡「说明」行、设置页「运行方式 / 稳定性」两卡
    与「关于」卡的技术细节行（控制接口 / 实现）、DPI 范围说明、宏「参数写法」长说明、
    灯带预览长说明、槽 0 说明卡、自动切换页退让说明与「在线模式专属」提示卡；
    各空状态提示缩为一句短语；后台服务状态文案精简为「运行中 · 当前 X 号槽 · N 条规则」。
18. **页面合并，8 页减为 4 页**（用户要求「设置/概览/性能融合一页，按键/灯光/槽位融合一页」）：
    - **概览**（page 0）= 概览 + 性能 + 设置：设备卡与统计、FLASH 之后依次是「性能」
      分节（DPI / 回报率统计、DPI 档位、修改 DPI、回报率）与「设置」分节
      （配置备份、开机启动、关于）；
    - **自定义**（page 1）= 按键映射 + 灯光 + 配置槽位，三个分节各自带绿色分节标题；
    - **宏**（page 2）、**自动切换**（page 3，仅在线模式）保持独立。
    实现上不改卡片内容，只把各块的条件改为目标页码并加分节标题——Slint 里同页多个
    `if` 块按声明顺序渲染，天然得到正确的分节顺序。侧栏从 7 项减为 3 项 + 在线模式组；
    顶栏标题与 `--page N` 参数同步收敛为 0–3。
19. **概览页二次压缩**（用户圈图反馈）：删掉「关于」卡；「FLASH 使用情况」卡压缩为
    统计卡下的一行 InfoRow（「Flash 剩余可用」）；「回报率」卡由标题+控件两行压缩为
    单行卡（左标签右 Chip，上下 8px padding 居中）；「开机启动」卡同样压缩为单行卡
    （徽章与按钮套 `VerticalLayout { alignment: center }` 保证 44px 卡内垂直居中）；
    「DPI 档位」与「修改 DPI」两卡合并为一张——档位列表下方直接放
    「修改 DPI + 输入框 + 写入」一行，去掉了重复的标题行。
20. **Apple HIG 风格整理**（用户反馈「UI 太丑」并给出 Apple 设计指南参考）：
    - **内容列宽度**：曾按 Apple HIG 的固定版心思路做过限宽居中（720px），但用户在
      宽窗口下反馈「太窄了，两边都空空的」，遂撤掉限宽、恢复内容铺满侧栏右侧的可用宽度。
      结论：这个程序的卡片本身已按行组织，铺满不像长文那样难读；限宽反而浪费空间。
      记录两条 Slint 坑，避免以后再走回头路：
      （1）限宽居中的第一版用「两侧弹性垫片 + `max-width` + stretch」，内容列命中
      上限后剩余空间被第一个垫片独吞，内容贴右（用户截图「全部偏向右边」）；
      （2）宽度绑定 `parent.width` 会与 ScrollView 的 content-width 形成绑定环，
      Slint 直接拒绝编译，只能用常量宽度；而常量宽度在窄窗口又会溢出。
    - **列表行圆角内缩高亮**：DPI 档位、物理按键、灯区、板载槽、宏清单、宏步骤、
      自动切换规则的选中/悬停背景从整条通到卡片边缘改为 `x: 8px` 内缩 + 8px 圆角，
      行内容 padding 16→24 与之对齐；按键表头与宏新建行同步 24px 对齐。
    - **删除冗余巨卡**：性能分节的「DPI / 回报率」两张 84px 统计卡与下方卡片信息重复
      （档位列表已有「生效中」高亮、回报率行已有选中 Chip），整行删除。
    - 自动切换页规则行内缩时保留「整行点击区在内容之前」的层级注释约定。

21. **应用图标 + 按键映射改版 + Flash 百分比**（用户要求「看图标知道是雷蛇的应用」、
    「不用显示原始参数、不用各种按键平铺，点物理按键切换」、「Flash 加剩余百分比」）：
    - **应用图标**：新建 `apps/razermate/assets/`，`razer-logo.svg` 是雷蛇三头蛇矢量路径，
      `app.ico` 由它渲染出 16/24/32/48/64/128/256 七档合成（深色圆角底 + 雷蛇绿渐变 +
      微弱辉光，小尺寸也能看出是绿色蛇形徽标）。`build.rs` 用 `windres` 把 `app.rc`
      编成 COFF 资源对象再 `cargo:rustc-link-arg` 链进 exe，资源管理器 / 文件属性据此显示图标
      与版本信息。**两个坑**：资源语言必须写 `LANGUAGE 0x00, 0x00`（中立），纯 1033 在中文
      Windows 上不回退；Slint 的 winit 后端不读 exe 图标，窗口默认挂系统通用图标，必须运行时
      `WM_SETICON`——但按模块句柄 `FindResource` 会报 `ERROR_RESOURCE_TYPE_NOT_FOUND`，
      最终改用 `ExtractIconExW`（按文件解析 PE 资源）取 HICON 再挂到窗口大小图标上。
    - **按键映射改成「点图改键」**：删掉整张物理按键表（ID / 动作 / 原始参数），改为
      左栏鼠标俯视示意图（形状见第 22 条，全部是热区），
      点哪个键右栏就切到哪个键的编辑区；滚轮左右倾斜用两个压边的窄热区配三角箭头。
      右栏标题行同时显示当前动作（`sel-button-action` 由 Rust 侧随按键列表算好），
      不再显示 `fn=` 原始报文。启动后自动选中左键一次（`auto-picked` 一次性标志，
      用户按「取消」收起后不会被刷新重新弹开）；槽位未上报的按键仍可点开，编辑区给出
      提示并禁用「写入」。
    - **Flash 剩余百分比**：`Flash 剩余可用` 一行改为「剩 85% · 78336 B 可用 / 共 92160 B
      （306 页）」，百分比按 `可立即使用 / 总容量` 计算，与板载页数同口径。

22. **鼠标示意图 ＝ 真机图 + 引线标注**（用户先后指出「不知道按键在鼠标哪里」「这是两颗按键」
    「狙键在前面」）：
    - **底图是真机渲染图**：`assets/basilisk.png` 原图 448×700 自带透明底，裁到 388×558 直接嵌入。
      机身、键缝、滚轮、蛇标、RGB 光晕全由图片呈现，不手绘——位置来自图片本身，画不歪。
    - **12 条引线标注（`Callout`）**：每条 = 锚点圆点 + 引线 + 文字标签。锚点和引线都写在底图的
      源图坐标里（`line` 是 `"M 2 268 L 130 274"` 这样的 Path 字符串，槽位类型 `string` 可以直接
      喂给 `Path.commands`），`Path` 用 `viewbox 388×558` 缩放，所以图片怎么缩线都钉在同一个键上。
      标签左右各一列、常显不隐藏——**不点也能一眼对上号**；点标签和点按键等价。
    - **热区表（`HitKey`）**：`ux/uy/uw/uh` 全是源图像素，渲染时换算成容器百分比。用固定 px 会和
      图片错开（图片被布局压窄时整体偏 25px），这条不能省。
    - **按键拓扑（这次被用户纠出来的两处错）**：
      1. 滚轮后面是**两颗独立按键**，不是一颗：**上＝滚轮模式（id 106）、下＝DPI（id 96）**
         （上下顺序以实物为准，别照直觉把 DPI 放上面）。
         之前把 106 当成「底面开关」画在图下方是错的——它就在滚轮后面；底面只剩 Profile（id 14）。
      2. 左侧拇指区从前到后是 **狙击（15）→ 前进（5）→ 后退（4）**。狙击键在最前面，不是最后面。
      3. 滚轮左右倾的锚点必须落在 "<" ">" 三角上（源 x 181–193 / 239–251）。左右主键的热区要让开
         滚轮槽和这两颗三角，否则三角被主键热区盖住、永远点不到。
    - **空闲态不点也看得全**：没选按键时，右侧卡片直接列出全部可改按键和当前动作（行本身也可点），
      配合左侧标注，键名、位置、动作三样同时在屏上。
    - **标定方法（可复用）**：截图里按颜色检出 12 个锚点圆点 → 最小二乘得缩放 0.5、原点 258.5/156.5
      → 12 个点与坐标表误差 ≤ 0.5px；再用 alpha 检查锚点是否压在机身上（12/12 都在）；
      最后做热区几何归属检查——每个锚点只命中自己的框（12/12），残余重叠只有滚轮边缘 1–9px 的碎片。
    - **踩过的坑**：Slint 组件根元素不能访问 `parent`，热区坐标要由调用处给或用 id 引用容器；
      标签行高必须 ≥ 行距，否则两行之间有 5–9px 点不到的缝；自动化点击脚本按标题匹配
      "Basilisk V3" 会打到 Chrome 里同名的标签页，必须用完整标题 `RazerMate — Basilisk V3`
      并把窗口置顶，否则点击会落到别的窗口上（这次排查绕了很久）。

23. **视觉系统重做**（用户贴了两张设计稿，要求「好好优化一下 UI，当前太丑了」）：
    - **四级深浅**：窗口底 `#080A0E` → 卡 `#151A21`（158° 微渐变）→ 卡内浮层
      `#1D232C` → 输入底 `#0E1218`；卡片加 1px 8% 白描边和 22px 投影，
      从「一块块灰板」变成浮在背景上的层。
    - **概览页重排**：主卡（真机渲染图 + B3 徽标 + 设备名 + USB/固件胶囊）
      → 四张指标卡（图标底 + 数值 + 箭头，紫/蓝/橙/绿分色）→ Flash 进度条
      → DPI 与回报率并排 → 设置（备份 + 开机启动开关）。原来这些是
      「一条分组标题 + 一张卡」竖着堆，信息密度低、视觉也散。
    - **真机图**：`basilisk.png` 四周补 11% 透明内边距另存为 `basilisk-hero.png`，
      原图是紧贴边缘裁的，直接用会在卡片右缘被切出一道直线；补边后缩到
      182×236 放在主卡右侧，底缘用渐变融进卡面。
    - **卡内标题组件 `CardHead`**：26px 圆角图标底 + 标题 + 右侧说明，
      替换掉所有「卡片外面挂 SectionHeader」的写法（共 8 处）。
    - **线性图标 `Glyph`**：15 种 16×16 图形（鼠标/键盘/宏/靶心/调色盘/齿轮/
      波形/上下传/箭头/刷新/电源/文件夹/对勾），纯 Rectangle + Path 描边，
      零贴图；颜色由调用处传，所以同一枚图标能当强调色也能当灰色。
    - **输入框自绘**：std-widgets 的 `LineEdit` 自带浅色底，在暗色卡里像贴了
      张白纸；改成 `TextInput` + 自绘底板（`Field`），聚焦时描边变绿。
    - **兼容坑**：① `Image` 没有 `border-radius`，要圆角得套一层带 `clip` 的
      Rectangle；② `Path.viewbox-width` 是**数字**不是长度，写 `16px` 报
      「Cannot convert length to float」；③ `TextInput.edited` 没有参数，
      参数版是 `LineEdit` 的；④ 布局里的固定宽度元素必须显式
      `horizontal-stretch: 0`，否则会被同排文字挤窄（Flash 进度条的填充
      因此跑到轨道中间）；⑤ 子元素默认 x 为 0 这条在嵌套 Rectangle 里不总成立，
      给填充块显式写 `x: 0` 才稳。
    - **对比度**：全套重算，辅助文字从 `#6D7787`（3.2:1）提到 `#838F9E`（5.32:1），
      10.5px 小字也过 AA。

24. **控件级修整**（用户贴了「回报率三连胶囊」「设置按钮绿边」「Flash 进度条浮在字上」
    「B3 徽标」四张局部截图）：
    - **回报率改分段控件**：125 / 500 / 1000 是互斥枚举，原来做成三个整宽胶囊，
      竖向吃掉 100px 还显得像三个开关。改成一行三格等宽的 `SegItem` 分段条
      （底槽 `#0D1116` + 3px 内边距，选中格浅绿底 + 绿描边 + 绿字），
      每格再加 9.5px 副标签「省电 / 均衡 / 竞技」，卡宽 216→232，内容整体居中，
      跟旁边更高的 DPI 卡并排时不再「贴顶留一大块空」。
    - **次级按钮绿边**：`Btn` 原来只按 primary 控 `drop-shadow-blur`，颜色和
      `offset-y` 无条件给值；blur=0 时 Slint 仍会画一圈硬阴影，暗底上就是按钮
      下沿一条洗不掉的绿线（「恢复最近备份」「打开目录」都有）。现在颜色置
      transparent、偏移归零，只有主按钮带绿光。
    - **Flash 进度条**：原先塞在 `HorizontalLayout` 里（固定 200px + 后面跟一条
      `horizontal-stretch: 1` 的说明文字），窄窗口下整条被挤到文字上方、浮在卡边。
      改成两行：上排「Flash 已用 + 右侧明细」，下排整宽 6px 轨道，宽度只跟卡宽走，
      不再参与 flex 分配。
    - **B3 徽标**：原先 B3 字下面兜一条 44×3 的小彩虹条，像贴纸。改为字居中、
      彩虹灯带压到块底 4px，靠块的 18px 圆角裁成一段弧，读作设备灯带。
    - **开机启动行**：标题 / 状态 / 副标题原来三截挤在同一行，像一句话。改为左侧
      两行（标题 + 状态小标签 / 副标题），右侧只留开关，行高 50→56 与备份条齐平。
    - **坑位补记**：`drop-shadow-blur: 0` 不等于「没有阴影」，颜色和偏移也要一起
      清掉；`HorizontalLayout` 里固定宽度 + 相邻 stretch 文字的组合在窄宽度下
      垂直位置会失控，宁可拆成上下两行。

25. **逐页排版审计**（用户反馈「很多地方都是歪的」，逐页截图核对概览 / 自定义清单态 /
    自定义编辑态 / 宏 / 自动切换，两种窗口宽度）：
    - **右侧编辑卡没撑满**：自定义页原本是「左图卡 + 两张互斥的 `if` 条件卡」做兄弟节点，
      选中按键后那张卡 `horizontal-stretch: 1` 不生效，右边空出约 60px，和下方灯区卡右缘
      明显参差。合并成**一张右卡**，只在卡内按 `sel-button` 切换「编辑面板 / 全键清单」，
      两态现在都精确撑到主区右缘。
    - **鼠标图上方灰杠**：`MouseMap` 用 26px 渐变盖住线缆断口，颜色写成 `#24272E`，
      比卡片上半部实际底色亮一截，成了一条横杠。改为 `#1A2029 → 透明`。
    - **灯带预览卡标题**：其它卡都用 `CardHead`（图标底 + 标题 + 右侧说明），只有这张
      是裸 `Text`，替换成统一组件，副说明走 `sub`。
    - **贴边**：灯效总览卡的 `HorizontalLayout` 只写了 `padding-left`，右侧「独立调光 /
      下面三个灯区各自设色」贴到卡片边框；补 `padding-right: 22px`。自动切换页
      「三区灯效 · 每区可独立设置…」是裸 `Text`，x 从卡左缘起（0 内边距），
      改成带 14px 内边距的 `HorizontalLayout`。
    - **空状态**：「还没有规则」「还没有虚拟槽」原来左对齐孤零零挂在卡片里，改为水平
      居中，并补上操作提示（填程序名选槽位点「添加 / 更新」、填名称后点「新建」），
      与宏页空状态风格一致。
    - **三区灯效拆两行 → 一行**：原来每区是「效果 Chip + 颜色圆点」一行、「亮度 +
      滑条 + 百分比」一行，颜色圆点与 60% 处的滑柄恰好落在同一 x，三区连成一列莫名
      对齐的绿点。抽出 `LedRow` 组件，把效果 / 颜色 / 亮度 / 数值压在同一行，
      三行严格对齐，卡片高度也随之减少。
    - **DPI / 回报率行**：输入框与「回报率」标签原本只隔 8px，两组控件挤成一条；
      加 14px 呼吸位、行距 8→10、DPI 输入框 90→100px。
    - **坑位补记**：Slint 的 `HorizontalLayout` 里，两张互斥 `if` 卡片做兄弟节点时
      `horizontal-stretch` 可能失效——把条件收进同一张卡的内部更稳；
      裸 `Text` / 裸 `HorizontalLayout` 放进 `VerticalLayout` 不会自动继承左右内边距，
      每一层都要自己写 padding。

26. **移除 B3 徽标 + 修正固定高度控件贴顶**（用户三张局部截图）：
    - **删掉 B3 框**：主卡高 176px，78px 的 B3 圆角徽标在 `HorizontalLayout` 里被顶到
      上沿，而标题 / 胶囊是垂直居中，两者天然错开；徽标本身也只是多余装饰。整块移除
      （含文字与底部灯带），身份区只留标题 + 两枚胶囊，左内边距 22px。
    - **按钮 / 开关「上下没对齐」**：Slint 的 `HorizontalLayout` 对**显式 `height`** 的
      子元素按交叉轴起点排布（贴顶），不会跟着左侧 `VerticalLayout { alignment: center }`
      的两行文字一起垂直居中——56px 高的条里 32px 按钮、24px 开关全压在上边框，
      下方空出 20~30px。修法：给右侧控件组套一层
      `VerticalLayout { alignment: center; }`（三枚按钮先收进一个 32px 高的横向布局，
      再整体居中），开关同样包一层，两者都落在条的正中。
    - **坑位补记**：这是全局性行为，凡「横向布局 + 固定高度控件 + 相邻居中文字」都可能
      出现；用纵向 layout 居中包一层，不要用 `padding-top` 硬顶（会把文字一起推偏）。
